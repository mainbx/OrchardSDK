## What exists today

Provider stub classes are available in `integrations/email`:

- `GmailService`
- `OutlookService`
- `ProtonMailService`
- `YahooMailService`

Each class currently provides:

- `sendMessage(to, subject, body, attachments?)`
- `listThreads()`
- `listMessages(threadId)`

These are intentionally placeholders and do not perform real provider API calls.
Stub methods currently perform only basic input checks (for example non-empty values and CR/LF header checks).
Providers share a common `BaseEmailService` helper and `EmailProvider` interface for consistent validation behavior.

## Configuration expectations

### Gmail

- Google OAuth app credentials.
- Gmail API scopes and token lifecycle handling.

### Outlook

- Microsoft Entra ID application credentials.
- Microsoft Graph Mail scopes and refresh token handling.

### ProtonMail

- Proton Mail Bridge connection details and credentials.
- IMAP/SMTP client wiring.

### Yahoo Mail

- Yahoo OAuth app credentials or IMAP/SMTP credentials.
- Provider-specific mailbox/thread mapping logic.

## Limitations

- No OAuth authorization flow.
- No API SDK calls.
- No IMAP/SMTP transport implementation.
- No inbox syncing, webhooks, or retries.
